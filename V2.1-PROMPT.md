# V2.1: present stems by derivation, syncretism by underspecification

The prompt for church-slavonic 2.1.0. Two designs from
`docs/OPEN-DESIGNS.md`, in order: (1) the present stem of a verb is
derived by the class, never stored on the lexeme line except for
suppletion; (2) a token whose readings are one lexeme in several cells is
an analysed token with an underspecified cell, not an ambiguous one. Read
`docs/DESIGN.md`, `docs/OPEN-DESIGNS.md`, `HANDOFF-PROMPT.md` and the
"2.0.0" entry of `CHANGELOG.md` first. Execute the parts in order; each
part ends with its gate measured, a CHANGELOG entry under "2.1.0 (in
progress)", a dated NOTES.md entry (decisions and findings), and a commit.

## Standing rules

- The lexicon holds lexical facts. A form the class produces is never
  stored; a stem the class can derive is never stored. Removing lines is
  the measure of success in Part 1; adding a rule that removes none is a
  failure.
- Gate on the measured numbers, never on self-consistency. Every number
  below is printed by `cargo xtask eval`, `cargo xtask import kaikki
  --pos verb`, `cargo xtask check-treebank` or a census command this
  prompt adds; record the number before and after.
- The round-trip invariant: `check-treebank` at zero mismatches over
  34,470 verses. An underspecified leaf renders its token byte-for-byte
  through every cell it names, or it does not enter the tree.
- Never guess. Underspecification records what the paradigm cannot tell
  apart; it never chooses between lexemes. Disambiguation by context is a
  later design (`docs/OPEN-DESIGNS.md` 1b) and is out of scope here.
- Class tables are generated: change `scripts/kaikki-to-classes.py` (OCS)
  and `scripts/legend-adj-verb-pron.py` (Synodal), never the tsv by hand;
  lexicon files are `include_str!`-embedded, so `cargo build` before any
  `xtask` sees an edit.
- Zero warnings (`cargo clippy --release -p church-slavonic -p
  church-slavonic-tools`); `cargo test --release` green in both crates;
  the game (`~/Desktop/code/vertograd`) untouched by Part 1 and Part 2
  except that its tests must still pass against the new lexicon.

## Part 0 — the census

1. Add `cargo xtask census stems --pos verb [--ocs]`: for every verb line
   with a stored numbered stem, classify the relation between the stored
   stem and the infinitive stem (the lemma minus -ти/-щи) into: `theme`
   (the infinitive stem minus its final vowel), `iot` (`theme` then
   `iotate`), `pal1`/`pal2` (`theme` then the palatalisation), `ov`
   (-ова-/-ева- → -ꙋ), `artefact` (the stored stem equals or contains a
   whole attested present form — the seeding's longest-common-prefix on a
   single form), `suppletive` (none of the above). Print the counts and
   ten examples per relation, for the OCS lexicon (1,442 lines expected)
   and the Synodal (113).
2. Add `cargo xtask eval --guess verbs [--ocs]`: leave-one-out over the
   verbs the lexicon holds with attested present cells — hide the lexeme,
   guess it from its lemma alone, compare every present, imperative and
   present-participle cell it attests — and print the share of cells the
   guess reproduces. This is the number Part 1 must raise.
3. Record both in NOTES.md. Gate: the census runs; the guessed-present
   number is printed for both recensions.

## Part 1 — present stems by derivation

1. **OCS verb classes by Leskien.** Rewrite the verb seeding in
   `scripts/kaikki-to-classes.py` so a class is (infinitive type, present
   type) and the stems column uses derivations, not per-lexeme letters.
   The present type is read from the attested first and third person
   singular against the derived candidates, in this order: `2=iot` (class
   IV: `pres.1.sg=2-ѭ`, `pres.2.sg=1-иши`, `pres.3.pl=1-ѧтъ`, the present
   passive participle on stem 2; class III with -j-: every present cell on
   stem 2), `2=ov` (-ова-/-ева- → -ꙋ: `2-ѭ`, `2-ѥши`), `2=cut` (theme-vowel
   drop without iotation: боꙗти → бо-иши), plain (class III with -aje-:
   `1-аѭ`, `1-аѥши`; class I consonant stems: `1-ѫ`, `2-еши` with
   `2=pal1` where the stem ends in a velar; class II -нѫти). The imperative
   takes `3=pal2` where the stem ends in a velar (рьци). The class name
   records the type (`V:IV:iot`, `V:III:j`, `V:III:aje`, `V:III:ov`,
   `V:I:C`, `V:I:k`, `V:II`), not the sampled endings.
2. **Derivations in OCS letters.** `iotate` and `palatalise_in` already
   serve both recensions; check the OCS outputs the tables need (щ/жд for
   the dentals, ѕ for the second palatalisation of г, the л-epenthesis)
   against Kaikki's own forms and add an OCS exemplar test in
   `crates/church-slavonic/tests/class_exemplars.rs` for one verb per
   class: любити → люблѭ/любиши, писати → пишѫ/пишеши, дѣлати →
   дѣлаѭ, вѣровати → вѣрꙋѭ, нести → несѫ/несеши, рещи →
   рекѫ/речеши/рьци, двигнѫти → двигнѫ.
3. **Re-import.** `import kaikki --pos verb --write`, then `import ud
   --pos verb --write`; the UD importer's present-stem inference
   (`present_stem`) becomes a fallback used only when no class derivation
   reproduces the attested present, and it must never store a stem equal
   to or longer than an attested form (the `artefact` class of the
   census).
4. **Synodal.** Run the same census on `syn/verbs.tsv`; where a stored
   numbered stem is a derivation the class could name, move the
   derivation into `legend-adj-verb-pron.py` (the Polyakov classes already
   carry `iot`; the inferred stems of Part 3 were read off attested forms
   for the same reason) and re-import `polyakov --pos verb --write`,
   `alypy --pos verb --write`, `ruwiktionary --pos verb --write`.
5. Gate, all measured before and after: stored numbered present stems in

## Part 2 — syncretism by underspecification

1. **Readings.** Add `Lexicon::readings(surface) -> Vec<Reading>` beside
   `analyze`: the analyses grouped by (lexeme, print), each `Reading {
   lexeme, cells: Vec<(Cell, alt)>, exact, print }` — one lexeme, every
   cell whose form prints this surface. `analyze` stays as it is (one
   analysis per cell) for consumers that want the flat list.
2. **The underspecified cell.** `cell::CellSet` (an ordered, deduplicated
   set of cells of one part of speech) with `name()` that factors the
   shared components and writes the disjunction where they differ:
   `nom|acc|voc.sg`, `long.pos.m|n.sg.gen`, `2|3.sg` for an aorist, and
   `parse(pos, text)` as its inverse. Every member of a set must be a
   cell the lexeme declares.
3. **The treebank leaf.** A token whose exact readings are one lexeme in
   several cells is *analysed*: the leaf carries the set in its features
   (`(n свѣтъ.n :case nom|acc|voc :num sg)`, `(adj мꙋдрый.a :case gen :num
   sg :g m|n :series long)`, `(v рещи.v :t aor :p 2|3 :num sg)`), `:alt`
   is the alternative index of the first cell, and rendering goes through
   the first cell — the invariant checks the token as before. The reader
   and writer of `treebank/node.rs` accept `|` in a feature value; the
   linter treats a disjunctive feature as satisfied when any member
   agrees (narrowing a set by agreement is disambiguation, out of scope;
   the linter may report that a set could be narrowed, as a note, not a
   finding). Several lexemes, or one lexeme with several prints for the
   same key, stay verbatim with `:amb n` — that is homonymy, and it is
   the band `docs/OPEN-DESIGNS.md` 1b addresses.
4. **The hand overlay.** Genesis 1 keeps its fully specified leaves; the
   lifter's underspecified leaves are what the auto-lift writes. Add a
   `cargo xtask narrow-hand` that lists, for each hand leaf, whether the
   analyzer's reading set contains its cell (a hand cell outside the set
   is a finding: the tree claims a cell the lexeme does not print).
5. **The numbers.** `check-treebank` splits the analysed column into
   "one cell" and "one lexeme, several cells", and the ambiguous column
   becomes "several lexemes"; `cargo xtask eval` reports Bible coverage
   the same four ways (one reading / one lexeme, several cells / several
   lexemes / none). Expect the analysed share to rise well above 23.4%
   and the several-lexemes share to be the honest size of the homonymy
   problem; record both.
6. Gate: zero mismatches; analysed (one cell) unchanged or higher;
   analysed (one lexeme, several cells) ≥ 0 recorded; several-lexemes
   share recorded; every underspecified leaf lists every cell of its
   lexeme that prints the token (a census command asserts it over the
   whole treebank); the game's tests green.

## What not to do

- Do not keep a stored present stem "for safety" where a derivation
  reproduces the attested forms; the census is the arbiter.
- Do not let an underspecified leaf pick a cell by frequency, position or
  habit: the set is the answer, and a narrower answer is disambiguation.
- Do not fold the several-lexemes band into the analysed share by any
  heuristic; report it.
- Do not edit a class tsv by hand.
