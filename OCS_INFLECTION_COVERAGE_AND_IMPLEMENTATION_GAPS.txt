OLD CHURCH SLAVONIC INFLECTION COVERAGE AND IMPLEMENTATION GAPS
================================================================

Status date: 2026-08-09
Released facade: old-church-slavonic 0.5.0
Released core: old-church-slavonic-core 0.4.0
Released dictionary: old-church-slavonic-dictionary 0.2.0


1. EXECUTIVE SUMMARY
====================

The library cannot inflect every possible Old Church Slavonic word or every
historically possible construction.

It does provide complete, lossless access to every form admitted from its pinned
dictionary snapshot. It also has productive rules for substantial parts of noun,
adjective, and verb morphology. Productive completion is deliberately refused when
the engine lacks the lexical class, principal parts, stem allomorphs, formation, or
variant policy needed to justify a result.

The central coverage problem is therefore not simply a shortage of individual
surface forms. It is a shortage of independently justified lexeme-level metadata,
combined with several formations that the current rule model cannot yet represent
fully. This is most serious for verbs.

Three different claims must remain separate:

1. Source coverage: a form is explicitly present in a pinned dictionary table.
2. Productive coverage: a form is generated from sourced or caller-supplied lexical
   facts and a documented rule.
3. Plausibility coverage: a form is generated from an inferred but uncertain
   lexical analysis.

The current ordinary API implements the first two conservatively. It does not yet
have an explicit third, predictive layer. That layer is the best way to achieve much
higher coverage for unattested but morphologically possible forms without falsely
calling them attested.


2. CURRENT COVERAGE CONTRACT
============================

The current resolver order is:

    exact dictionary table cell
      -> independently sourced dictionary metadata
      -> reviewed cell-specific override
      -> productive core rule
      -> typed failure

The engine never catches an unsupported result and replaces it with a frequent
class, a neighboring grammatical cell, a question-mark sentinel, or an unrelated
language's form.

For a source-listed cell, the registry is complete and deterministic. For a missing
cell belonging to a known lemma, generation succeeds only if the required metadata
exists. For a lemma unknown to the dictionary, the rule-only API can generate forms
only when the caller explicitly supplies its lexical class, stems, formations, and
other required facts.

This means that "all source cells are reachable" does not mean "all grammatical
cells for all OCS lexemes are known." A dictionary paradigm key set contains every
key admitted from that dictionary entry, including its omissions.

4. CURRENTLY SUPPORTED MORPHOLOGICAL SURFACE
============================================

Nouns
-----

The facade exposes seven cases and singular, dual, and plural. Exact dictionary
tables take priority. Productive rules cover documented regular hard o-/a-stems,
soft jo-/ja-stems, i-stems, u-stems, and the supported n/nt/r/s/v consonant-stem
systems when the lexeme class and required metadata are known.

Adjectives
----------

Short and long adjective agreement is represented across case, number, gender,
and animacy. Hard and soft productive classes are supported. Dictionary-listed
comparative citations are available, but there is no general comparative generator
or full comparative declension API.

Determiners, pronouns, and numerals
----------------------------------

The ordinary API has typed case-number-only, person-indexed, and gender-indexed
closed-class shapes. These APIs are exact views of audited dictionary cells. They
are not productive general declension engines.

Finite verbs
------------

The word-level finite API represents present, imperfect, and aorist person-number
cells. Exact dictionary cells take priority. Productive generation is available
when the required independent system metadata is known.

Imperatives
-----------

The six historically morphological imperative cells are modeled. First singular,
third dual, and third plural expressions made with "да" are periphrastic and are
outside the word inflector.

Non-finite forms
----------------

The API covers dictionary or supported productive infinitives, supines, verbal
nouns, and gender-number l-participles. Irregular/root supines and forms requiring
unknown stems remain table-backed.

Participles
-----------

Present active, present passive, past active, and past passive participles are
modeled as independent verbal formations followed by short/long adjective
agreement. Formation identity, competing analyses, source variants, and traces are
preserved.


5. COMPLETE IMPLEMENTATION GAP INVENTORY
========================================

5.1 Lexical coverage and unknown lemmas
---------------------------------------

- The 3,081-lexeme registry is a pinned Wiktionary-derived snapshot, not a complete
  historical OCS lexicon.
- Unknown ordinary lemmas are not automatically assigned a noun class, adjective
  class, present class, aorist type, or principal parts.
- A citation form alone is often insufficient to determine a unique paradigm.
- Homographs and competing lexical analyses are real. There are currently 112
  ambiguous bare lemma/part-of-speech pairs.
- The explicit core can generate an unknown word only after the caller supplies
  the relevant lexical analysis.

5.2 Nouns
---------

- Automatic class inference for unknown nouns is absent.
- Irregular, suppletive, heteroclitic, indeclinable, or insufficiently classified
  nouns remain exact-table or caller-metadata cases.
- A citation ending can be compatible with more than one stem class; the library
  does not yet return ranked possible classes.
- Source tables sometimes omit lexical animacy. The engine requires explicit
  animacy wherever masculine accusative behavior depends on it.
- No phrase-level case government determines which noun cell a preposition, verb,
  numeral, or construction requires.

5.3 Adjectives and comparison
-----------------------------

- Automatic hard/soft or irregular class inference for an unknown adjective is
  absent.
- Comparative support is limited to source-listed citation forms.
- There is no productive comparative stem generator or general comparative
  declension system.
- There is no superlative construction or phrase-level comparison realization.
- Wiktextract flattens short and long adjective table blocks without reliable
  per-row form tags; the extractor currently depends on fixture-tested positional
  sentinel blocks.

5.4 Pronouns and determiners
----------------------------

- The typed APIs cover only coherent source-backed feature shapes.
- There is no generalized productive pronoun declension engine.
- The library intentionally has no catch-all optional-dimension pronoun API.
- Pronoun clitic/full-form selection, forms after prepositions, and syntactic
  placement are outside the inflector.
- New or hypothetical closed-class lexemes should not be generated merely by
  analogy without explicit evidence.

5.5 Numerals
------------

- Only eight pinned numeral lexemes have ordinary typed coverage.
- There is no arbitrary integer-to-OCS word generator.
- There is no productive cardinal, ordinal, collective, or compound numeral
  system.
- There is no numeral declension composition or numeral government of noun phrases.
- There is no traditional Cyrillic numeral parser/formatter or titlo-aware numeral
  notation utility.

5.6 Verb present system
-----------------------

- Productive dictionary metadata covers 121 of 711 verb lexemes.
- Only the currently admitted IA1, IA2, II1, II2, and II3 class analyses are
  automatically available from the dictionary metadata pipeline.
- Present-stem alternations and first-singular allomorphs cannot safely be guessed
  from every infinitive.
- Unknown verbs have no ranked present-class classifier.
- Irregular presents remain table-backed unless explicitly modeled.

5.7 Imperfects
--------------

- Productive dictionary metadata covers 150 of 711 verb lexemes.
- Automatic Palatalized-A selection is absent because the current source spelling
  cannot reliably recover the underlying velar.
- The only admitted productive variant policy is UncontractedOnly.
- Contracted imperfect distribution is not generalized.
- Suppletive and lexically exceptional imperfects are table-backed, except for the
  reviewed missing cells of "бꙑти".
- Corpus mismatches mix contraction, suppletion, abbreviation, editorial spelling,
  and unsafe principal-part selection. Aggregate counts do not justify one global
  contracted variant.

5.8 Aorists
------------

- No aorist metadata row in the current dictionary snapshot survives both the
  typed 1sg diagnostic and an independent exact cross-cell check.
- Automatic dictionary-backed productive aorist coverage is therefore zero.
- The explicit core implements asigmatic and new ox-aorist rules when a caller
  supplies the required analysis.
- Primary and secondary sigmatic aorists are typed but explicitly unsupported.
- A complete sigmatic representation still needs independently sourced:
    * root-grade or pre-sigmatic stem;
    * singular base;
    * non-singular base;
    * separate 2sg/3sg base where required;
    * s/x seam policy;
    * optional final -тъ variant policy.
- Aspect must not select an aorist formation.
- Suppletive aorists of "бꙑти", "дати", "ѣсти", "вѣдѣти", "хотѣти", and
  motion verbs remain table-backed unless a deliberately audited root analysis is
  provided.

5.9 Imperatives
---------------

- Productive dictionary metadata covers 73 of 711 verb lexemes.
- All automatically admitted records are currently i-series.
- Automatic yat-series selection is absent because the necessary diagnostic cells
  are missing or contradictory.
- Optional plural variants such as -ꙗмъ/-ꙗте remain table-backed.
- Periphrastic commands with "да" are syntactic constructions, not single-word
  paradigm cells.

5.10 L-participles and analytic verb constructions
--------------------------------------------------

- Productive l-participle metadata covers 185 verb lexemes.
- Irregular stems remain table-backed.
- The library does not assemble l-participles with auxiliaries or subjects.
- There is no phrase-level future, perfect, pluperfect, conditional, or finite
  passive realizer.
- The finite word API deliberately contains only present, imperfect, and aorist.

5.11 Non-l participles
----------------------

- Metadata coverage ranges from 134 to 186 verb lexemes by participle system.
- Automatic selection of special past-active final-j deletion and ov-to-u seams is
  absent; explicit callers can choose them.
- Some possible formation subtypes have no automatically admitted metadata.
- Approximately 153,310 declined participle source rows are rejected because the
  current Wiktextract snapshot does not preserve a complete, independently
  verifiable participle-kind table-block identity.
- Citation participles are retained, but cannot prove their own generated form in a
  leakage-controlled evaluation.
- Participles that are semantically or lexically unavailable for a verb must not be
  generated merely because an ending can be attached.

5.12 Irregular and suppletive verbs
-----------------------------------

- Apart from reviewed "бꙑти" imperfect cells, important irregular verbs are
  predominantly table-backed.
- High-frequency irregular systems need lexeme-specific principal parts and
  formation policies, not broad suffix heuristics.
- Prefixation does not always make an irregular base predictable without an
  explicit rule about which allomorphy is inherited.

5.13 Orthography and manuscript variation
------------------------------------------

- Lemma validation recognizes Cyrillic and Glagolitic and preserves historical
  letters and combining marks.
- Productive rules emit Cyrillic endings; Glagolitic is exact-source-only.
- Cyrillic and Glagolitic are not automatically transliterated.
- Lookup does not strip accents, breathing marks, titla, palatalization marks, or
  historical letters.
- There is no manuscript abbreviation expansion, titlo expansion, OCR correction,
  diplomatic transcription, or later-recension normalization.
- There are no explicit manuscript/editorial orthography profiles.
- Source romanization is metadata, not a guaranteed algorithmic transliteration.

5.14 Syntax and multiword realization
-------------------------------------

- The library inflects words; it does not generate syntax.
- There is no adjective/determiner/participle plus noun phrase builder.
- There is no preposition or verb case-government engine.
- There is no numeral-government engine.
- There is no auxiliary selection or agreement for perfect, pluperfect, future,
  conditional, or passive constructions.
- There is no pronoun-clitic placement or full/short form selection by context.
- There is no coordination, negation, word-order, or sentence-realization layer.

5.15 Reverse analysis and text utilities
----------------------------------------

The dictionary crate already provides:

- OCS-to-English lookup;
- English-to-OCS ranked semantic search;
- source-attributed examples;
- exact source-form reverse lookup;
- generated-form reverse lookup;
- token analysis;
- rendered-text known/unknown checking;
- game-vocabulary manifest linting.

However:

- reverse grammatical features are still exposed as strings rather than the
  facade's typed cell structures;
- the analyzer is not yet a unified first-class morphology API;
- it does not rank every possible productive analysis of an unseen surface form;
- it does not expose calibrated confidence or the assumptions behind speculative
  analyses;
- it does not perform sentence-level disambiguation.

5.16 Data and extraction constraints
------------------------------------

- Runtime dictionary forms come from a pinned English Wiktionary/Kaikki snapshot.
- Optional UD PROIEL and native Syntacticus/PROIEL/TOROT inputs are evaluation
  sources, not bundled runtime lexical authority.
- Malformed Wiktextract finite rows are rejected rather than repaired by guessing.
- A spurious l-participle tag appears on some finite rows.
- Rows marked error-unrecognized-form are rejected.
- Personal/reflexive tables are repeated on form-of pages and must not create fake
  lexemes.
- The current data pipeline needs more independently licensed lexical and
  principal-part sources, while retaining provenance and source-specific spelling.


6. WHY COVERAGE IS SPOTTY
=========================

Coverage is uneven for three different reasons:

1. Source sparsity
   Wiktionary does not list every lexeme or every cell, and some table exports lose
   distinctions needed for safe extraction.

2. Missing lexeme metadata
   The core may already know an ending rule, but the facade cannot choose the rule
   or stem for a particular lemma. This is the dominant current verb problem.

3. Missing rule expressiveness
   Some systems, especially sigmatic aorists and contextual manuscript variants,
   require more independent allomorphs and policies than the current structures can
   represent.

Adding more surface-form rows helps source coverage, but adding one trustworthy
principal-part analysis can complete many cells. Therefore, the most efficient path
is to acquire and infer reusable lexeme metadata rather than hand-enter every
surface form.


7. PROPOSED HIGH-COVERAGE PREDICTION LAYER
==========================================

The strict, source-backed API should remain available. Higher coverage should be
an explicit policy choice.

Suggested modes:

    Strict
        Exact table cells, independently sourced metadata, and reviewed overrides.
        This is the current ordinary behavior.

    Productive
        Permit an inferred lexical analysis only when one analysis is uniquely
        compatible with every available source fact and meets a calibrated
        confidence threshold.

    Exploratory
        Return every grammatically compatible ranked analysis and its forms. Never
        silently select one class.

Possible API shape:

    let inflector = Inflector::new(GenerationPolicy::Productive);
    let result = inflector.finite(
        "правити",
        FiniteTense::Imperfect,
        Person::Third,
        Number::Plural,
    )?;

Every result candidate should include:

    Candidate {
        forms,
        lexical_analysis,
        confidence,
        assumptions,
        supporting_evidence,
        contradicting_evidence,
        source,
        trace,
    }

Suggested provenance categories:

    DictionaryTable
    DictionaryPrincipalPart
    CuratedGrammarOverride
    ExplicitCallerMetadata
    InferredLexicalMetadata
    AnalogicalPrediction
    CorpusObservation

An inferred or analogical form must never be relabeled as attested.


8. METHODS FOR RAISING PRODUCTIVE COVERAGE
==========================================

8.1 Infer reusable lexical metadata
------------------------------------

Infer a complete system analysis from all available cells instead of memorizing a
single missing form. For a verb, independent metadata may include:

    present class
    present stem
    first-singular allomorph
    imperfect stem
    imperfect formation
    imperfect contraction/variant policy
    aorist formation
    aorist singular base
    aorist non-singular base
    aorist 2sg/3sg base
    aorist seam and optional-ending policy
    imperative stem and series
    l-participle stem
    four participial stems and formations
    lexical restrictions and irregularity flags

Each candidate analysis must reproduce every independent available cross-check.
Contradictory analyses must be rejected or returned separately as ambiguity.

8.2 Build ranked class inference
--------------------------------

For lexemes without sufficient metadata, rank compatible analyses using:

- citation and infinitive shape;
- source headword conjugation or declension labels;
- available principal parts;
- stem-final phonology;
- derivational suffixes;
- aspect, without using aspect to choose unrelated formations;
- behavior of fully classified analogous lexemes.

For a completely unknown lemma, return multiple candidates when the spelling does
not determine a unique class. Top-k recall is more honest and useful than a forced
top-1 answer.

8.3 Add paradigm completion
----------------------------

Provide a completion API whose rows retain their epistemic status:

    Attested
    SourcedPrediction
    InferredPrediction
    AmbiguousPrediction
    HistoricallyInvalid
    Unsupported

This lets an application use plausible forms while displaying or enforcing its own
confidence policy.

8.4 Curate common irregular lexemes
-----------------------------------

Add reviewed complete system records for high-frequency irregular verbs, beginning
with:

    бꙑти
    дати
    ѣсти
    вѣдѣти
    хотѣти
    major motion verbs
    frequent prefixed derivatives that inherit irregular allomorphy

A small, well-sourced irregular lexicon can improve real-text coverage more than a
large unsafe heuristic.

8.5 Recover declined participle blocks
---------------------------------------

Implement an atomic table-block parser using the original template/table heading,
tense/voice identity, citation participle, complete agreement dimensions, and
consistency with independently derived stems. Do not infer participle kind from a
flattened row in isolation.

8.6 Expand source adapters
--------------------------

Add independently licensed dictionary, grammar, and corpus adapters. Preserve:

- exact source identity and version;
- licensing;
- raw source spelling;
- canonical display spelling;
- normalized lookup key;
- whether a row is lexical authority, grammatical authority, or evaluation-only;
- conflicts rather than source-priority erasure.

8.7 Add noun and adjective classifiers
---------------------------------------

Infer ranked compatible stem classes from citation endings, gender, animacy, stem
shape, and available cells. Never present an ending-only guess as certain. Keep
irregular and consonant-stem alternatives visible.

Closed classes should generally remain lexicon-backed.


9. REQUIRED EVALUATION FOR PREDICTIVE FORMS
===========================================

9.1 Masked-cell completion
--------------------------

Remove one source cell, derive metadata from the remaining independent cells, and
test whether the hidden cell is recovered. Equivalent and same-spelling cells must
also be excluded to prevent leakage.

9.2 Lemma-disjoint evaluation
-----------------------------

Hold out complete normalized lemma keys when developing class inference. Homographs
and parts of speech sharing that key must remain in the same partition.

9.3 Independent-corpus evaluation
----------------------------------

Evaluate against pinned external corpora without using the target token as lexical
metadata. Keep separate:

- raw diplomatic agreement;
- NFC/lowercase agreement;
- orthographic-profile agreement;
- returned-form coverage;
- top-1 correctness;
- top-k correctness.

9.4 Confidence calibration
--------------------------

A prediction labeled 90 percent should be correct approximately 90 percent of the
time on held-out data. Report coverage/precision curves for Strict, Productive, and
Exploratory policies. Do not report accuracy only among returned forms without also
reporting abstention.

9.5 Per-system reporting
------------------------

Keep separate metrics for:

    noun class and complete cell
    adjective class/form and complete cell
    present class and cell
    imperfect formation/policy and cell
    aorist formation/seam/policy and cell
    imperative series and cell
    l-participle
    each of the four participle systems
    irregular versus regular lexemes
    source, inferred, and analogical generation paths


10. USEFUL ADDITIONAL UTILITIES
===============================

10.1 Typed morphological analyzer and lemmatizer
------------------------------------------------

Promote the existing reverse indices into a first-class API returning typed noun,
adjective, finite-verb, imperative, l-participle, participle, pronoun, determiner,
and numeral cells. Preserve every lemma candidate, stable lexeme ID, variant,
provenance, and confidence.

10.2 Per-lexeme capability inspection
--------------------------------------

Provide an API such as:

    capabilities("глаголати", PartOfSpeech::Verb)
      .supported_cells()
      .missing_metadata()
      .unsupported_formations()
      .prediction_candidates()

Applications should not have to trial every cell to discover why a paradigm is
incomplete.

10.3 Principal-part audit and metadata editor
---------------------------------------------

Build a CLI that identifies missing verb-system metadata, shows candidate source
cells and contradictions, compares proposed analyses against every cross-check, and
emits reviewable metadata records rather than editing generated code.

10.4 Constrained phrase realizer
--------------------------------

Add a separate layer for:

- adjective, determiner, and participle agreement;
- noun phrase case and number;
- preposition government;
- numeral government;
- auxiliary plus l-participle constructions;
- pronoun full/clitic/after-preposition selection.

Keeping this separate preserves the word inflector's clear contract.

10.5 Productive numeral system
------------------------------

Add integer spelling, cardinal/ordinal distinctions, compound numeral realization,
declension, governed noun phrases, and optional traditional Cyrillic numeral
notation.

10.6 Explicit orthography profiles
-----------------------------------

Add opt-in, named conversions among canonical Cyrillic, Glagolitic, scholarly
romanization, and selected manuscript/editorial conventions. Every conversion
should report loss or ambiguity rather than promise a universal bijection.

10.7 Attestation and concordance API
------------------------------------

Given a lemma or form, report whether it is a dictionary citation, exact table
cell, productive prediction, dictionary example token, external corpus observation,
or unattested prediction. Link it to source identities and available example
references.

10.8 Batch, JSON, serde, and WASM support
----------------------------------------

Add optional serde support for grammar cells, structured results, errors, evidence,
and analyses; a batch JSON CLI; and feature-gated smaller data packages for browser
use.

10.9 Corpus and vocabulary QA
-----------------------------

Extend the existing text checker with typed analyses, suggested lemmas, predicted
forms, confidence thresholds, manuscript profiles, and explainable unknown-token
diagnostics.


11. RECOMMENDED IMPLEMENTATION ORDER
====================================

1. Introduce explicit Strict, Productive, and Exploratory generation policies.
2. Add candidate analyses, assumptions, confidence, and inferred-metadata
   provenance without weakening strict behavior.
3. Generalize the existing leakage-controlled metadata derivation into a reusable
   masked-paradigm completion framework.
4. Expand the aorist model with the independent allomorph and seam fields needed
   for sigmatic formations.
5. Derive or curate verb metadata for all 711 current dictionary verb lexemes.
6. Add contracted imperfect and yat-series imperative policies with lexeme-level
   evidence.
7. Implement the atomic declined-participle table-block parser.
8. Add reviewed complete records for common irregular verbs.
9. Build ranked unknown-lemma verb class inference.
10. Add ranked noun and adjective class inference.
11. Promote reverse analysis to a typed first-class morphology API.
12. Add phrase realization and productive numerals as separate higher-level layers.
13. Add explicit orthography/transliteration profiles and corpus concordance tools.


12. NON-NEGOTIABLE SAFETY AND QUALITY RULES
===========================================

- Never describe a generated form as attested unless a pinned source contains it.
- Never use Interslavic, Slovowiki, Russian, or another later Slavic language as OCS
  lexical authority.
- Never select a verb formation from aspect alone.
- Never silently collapse multiple source variants or competing analyses.
- Never return a bare string that hides confidence, provenance, or alternatives.
- Never let an inferred row displace an exact dictionary row.
- Never tune and evaluate a classifier on the same lemma partition.
- Never use a target corpus token as its own principal-part evidence.
- Preserve historically invalid cells separately from implementation gaps.
- Preserve unsupported-but-conceptually-valid cells separately from contradictory
  metadata.
- Keep runtime morphology free of file, network, JSON, TSV, XML, and Lua access.
- Regenerate committed data through the extractor and xtask pipeline; do not edit
  generated registry files manually.


13. PRACTICAL DEFINITION OF SUCCESS
===================================

A higher-coverage release should demonstrate all of the following:

- all current 134,761 dictionary cells and 137,406 ordered variants still round
  trip exactly;
- strict mode retains the current fail-closed semantics;
- productive mode materially raises held-cell availability while maintaining a
  guarded high conditional correctness rate;
- exploratory mode reports high top-k recall without hiding ambiguity;
- aorist, imperfect, imperative, and participle metrics are reported separately;
- confidence is calibrated on lemma-disjoint data;
- every predicted result exposes its assumptions and evidence;
- every paradigm row distinguishes attested, sourced prediction, inferred
  prediction, ambiguity, historical invalidity, and unsupported implementation;
- real-world corpus recall improves without treating diplomatic spelling mismatch
  as proof of a wrong morphological analysis;
- source licensing and provenance remain visible through generated output.
